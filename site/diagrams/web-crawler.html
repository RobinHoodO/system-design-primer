Client

Step 4 · Search pages

What it is

The user enters a search term and sees relevant pages.

Its job here

It asks DNS where to connect, then sends the search request to Load Balancer. It receives titles and snippets in the result.

DNS

Step 4 · Search pages

What it is

DNS resolves a name so the client can find the service.

Its job here

It receives the lookup from Client and gives back the connection destination. Client then sends its request to Load Balancer.

Trade-off

DNS is an extra dependency before the request reaches the crawler system.

Load Balancer

Step 4 · Search pages

What it is

A load balancer distributes incoming requests across service instances.

Its job here

It receives the search request from Client and passes it to Web Server. The stacked copies show that it can have several instances.

Trade-off

It adds another component to operate before requests reach Web Server.

Web Server

Step 4 · Search pages

What it is

The public web layer accepts the client request.

Its job here

It receives traffic from Load Balancer and forwards the request to Query API. The response returns through this web layer to Client.

Trade-off

Using a reverse proxy adds another hop in the request path.

Query API

Step 4 · Search pages

What it is

The public REST API parses a search query.

Its job here

Web Server forwards the request here. Query API uses Reverse Index Service, then Document Service, to return matching pages with titles and snippets.

Trade-off

Query parsing adds work before results can be returned.

Reverse Index Service

Step 2 · Index words

What it is

This service builds a reverse index of words to pages.

Its job here

Index Queue delivers crawl jobs to it. It returns documents that match a query to Query API.

Trade-off

Generating the index is separate work from crawling pages.

Document Service

Step 3 · Build documents

What it is

This service creates static titles and snippets for pages.

Its job here

Document Queue delivers crawl jobs to it. It passes page documents to Memory Cache and Query API uses it to return titles and snippets.

Trade-off

Titles and snippets are static and do not change for each query.

Reverse index queue

Step 1 · Crawl pages

What it is

A queue holds reverse-index jobs.

Its job here

Crawler Service adds a job here after it crawls a link. The queue hands that job to Reverse Index Service.

Trade-off

A queue separates crawling from indexing, so the work does not have to finish in the crawler loop.

Crawler Service

Step 1 · Crawl pages

What it is

The service processes the highest-ranked page link in a loop.

Its job here

It reads ranked links and signatures from NoSQL, then adds jobs to both queues. It writes the crawled link and page signature back to NoSQL.

Examples

  • Jaccard index
  • Cosine similarity

Trade-off

It must detect similar pages so a graph cycle does not become an infinite loop.

Memory Cache

Step 3 · Build documents

What it is

A memory cache keeps generated page documents ready to read.

Its job here

Document Service feeds it with titles and snippets. Query API can use those documents after Reverse Index Service finds matching pages.

Trade-off

Cached data can require an update strategy as pages are crawled again.

In the primer

Cache › When to update the cache →

✕

NoSQL Database

Step 1 · Crawl pages

What it is

A key-value NoSQL database stores links to crawl and crawled links with signatures.

Its job here

Crawler Service reads the next ranked link and checks similar page signatures here. It then removes the link to crawl and inserts the crawled link and signature.

Examples

  • Redis

Trade-off

Choosing SQL or NoSQL depends on the use cases and trade-offs.

1 · Crawl pages

Crawler Service pulls ranked links, checks crawled signatures, and sends indexing and document jobs through queues.

It stores processed links and signatures in NoSQL.

2 · Index words

Reverse Index Service creates the map from words to the pages that contain them.

The queue lets indexing run separately from crawling.

3 · Build page documents

Document Service creates static titles and snippets for pages.

Generated documents are ready for a later search response.

4 · Search pages

Client reaches Query API through DNS, Load Balancer, and Web Server.

Query API uses the reverse index and page documents to return relevant pages.
