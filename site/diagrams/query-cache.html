Query API

What it is

The Query API parses and processes a search query.

Its job here

It receives the web request and checks the Memory Cache. On a miss, it asks the Reverse Index Service for matching documents.

Reverse Index Service

What it is

This service finds documents that match a query.

Its job here

It receives the normalized query from the Query API. It ranks matching results and passes the top ones to the Document Service.

In the primer

Database › Use good indices →

✕

Document Service

What it is

This service returns document titles and snippets.

Its job here

It receives top matches from the Reverse Index Service. It returns contents for the Query API to place in the Memory Cache.

In the primer

Database › Document store →

✕

Memory Cache

What it is

The Memory Cache holds query results in memory.

Its job here

It receives lookups from the Query API. On a hit it moves the entry to the front of the LRU list and returns cached contents; on a miss, the Query API uses the Reverse Index Service.

Examples

  • Redis
  • Memcached

Trade-off

Limited memory means older entries need to expire.

1 · Cache hit

Popular queries return from the Memory Cache.

The API updates the entry’s position at the front of the LRU list and returns cached contents.

2 · Cache miss

The API finds, ranks, and enriches matching documents.

The result is placed at the front of the Memory Cache’s LRU list.

3 · Cache refresh

A time to live refreshes cached entries.

Use it when page contents, pages, or page ranks change.
